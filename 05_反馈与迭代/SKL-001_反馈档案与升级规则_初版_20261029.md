# SKL-001｜反馈档案与升级规则

> 初版 v0.2｜目的：让真实使用持续改善产品，而不是让单个意见直接改写产品逻辑。

## 1. 两个池，不能混用

### A. 质量反馈池

记录 Skill 的判断、追问、输出是否有用。只存去识别摘要，不保存原始客户材料、截图、联系方式或项目名称。

### B. WorkBuddy 合规异常池

记录一条反馈或候选改动是否缺少必要字段、权限、版本、人工确认或权益说明。它不评价产品判断好坏，只判断能否进入正式管理与发布流程。

任何不符合管理要求的记录，停留在异常池并生成“待补项”；不得自动同步到正式反馈库或发行版本。

## 2. 质量反馈的最小字段

```text
feedback_id：FB-YYYYWW-序号
asset_id：SKL-001
版本：
来源：自测 / 访谈 / 平台反馈（不记录个人身份）
使用模式：快速初诊 / 标准访谈 / 内部评审
项目类型：使用预设分类，不写可识别名称
脱敏问题摘要：
标签：触发错误 / 来源混淆 / 基础提资遗漏 / 内容提资遗漏 / 方案命题不足 / 风险误判 / 输出格式 / 安全边界 / 其他
严重度：P0 阻断 / P1 高 / P2 常规 / P3 建议
人工修改了什么：
是否可泛化：否 / 待观察 / 是
建议动作：修复 / 补测试 / 观察 / 拒绝
关联测试 ID：
状态：待分析 / 已批准 / 已进候选版本 / 已发布 / 拒绝
```

## 3. 从反馈到升级的规则

```text
单次反馈
  → 去识别与分类
  → 判断：单次偏好 / 行业条件 / 候选通用规则
  → 你决定：做 / 不做 / 继续观察
  → 增加或修改原子测试
  → 修改候选版本
  → 回归测试通过
  → 人工确认后进入版本说明
```

- **单次偏好**：仅影响当前案例或由用户临时指定，不写进默认行为。
- **行业条件**：只进入对应行业判断包，例如空间类项目的场地和制作依赖。
- **候选通用规则**：至少有重复证据，或由你明确批准后，才进入核心逻辑。

## 4. 你可直接使用的调教指令

| 你说的话 | 我应当做什么 |
| --- | --- |
| “这个结论太武断。” | 降低确定性，改为待验证假设或选项 |
| “这只是内部方案解读。” | 改标为内部方案草案，不得写成客户原始需求 |
| “这是大纲前必须拿到的资料。” | 归入基础资料清单，并标注影响的工作阶段 |
| “这是分区深化时再补的内容。” | 归入大纲后提资，不把它作为前置阻断条件 |
| “这类项目必须先问场地。” | 记录为行业规则候选，并新增相应测试 |
| “这只是某客户习惯。” | 只保留为当次偏好，不进入产品规则 |
| “以后不要先问预算。” | 标记为待决定的交互策略，与你确认适用范围 |
| “把这次修改变成下一版规则。” | 生成变更说明、测试影响与候选版本建议 |

## 5. WorkBuddy 合规检查字段

进入正式管理或预览候选版本前，至少检查：

- 资产 ID、版本、变更原因与责任人是否存在；
- 是否完成去识别处理；
- 是否明确对应的测试与结果；
- 是否标明是否需人工确认；
- 是否包含未经批准的私有方法、案例、客户或资料；
- 是否属于可发布范围，或只应留在私有开发区。

若任一项不符合，输出异常清单：问题、缺失项、需补负责人、是否阻断发布。系统只能提示与归档，不能自动发布、自动上架或自动改变产品规则。
